# External PDF backends and privacy

All new services are opt-in. Local paragraph translation remains the default. Cloud parsers require whole-file upload consent. None is automatically added to the free fallback list.

## Local bridge
Install BabelDOC or PDFMathTranslate-next in a local Python environment. Configure its model using its own CLI config file; keep it private. Verify the CLI works on a sample first. BabelDOC accepts `--config`, PDF2zh-next `--config-file`. Generate a strong token with `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`. Set `BR_LOCALPDF_TOKEN` and `BR_BABELDOC_CONFIG` and/or `BR_PDF2ZH_CONFIG` (private local config file paths). Run `python3 scripts/local_pdf_server.py --port 8787`. Enter the same token and loopback URL in Zotero, select the engine and export. The server accepts only fixed engine/output choices, uses temporary directories, no shell, a 30-minute subprocess timeout and one job at a time. It expects exactly one upstream mono/dual PDF; if watermark modes emit multiple files, configure the upstream output mode yourself. Left/right pairs upstream mono with original; unequal page counts rejected. Stacked uses upstream dual format, not paragraph-level stacked layout. Cancellation stops waiting; subprocess may continue. Engine may use remote models and download assets, not guaranteed offline. No auto-install/start or automatic cloud fallback.
Upstream: https://github.com/funstory-ai/BabelDOC and https://github.com/PDFMathTranslate/PDFMathTranslate-next.

## Cloud parsing
Doc2X official v2 preupload, signed PUT and status with v2/v3-2026; Mathpix v3 multipart, status and lines.json with App ID/App Key. Both map text to physical page numbers, not invented paragraph coordinates. PDF.js alignment and continuation rules apply. Mathpix requests improve_mathpix=false, not zero-retention guarantee. Both may charge. Keys stored in Zotero preferences. Docs: https://doc2x.noedgeai.com/help/en/api/doc2x-api-v2-pdf-interface.html and https://docs.mathpix.com/reference/post-v3-pdf.

## Text
SiliconFlow, OpenRouter and Google Cloud Basic v2: separate credential profiles, fixed official endpoints. Free model selection is not unlimited. Cloud billing/API must be enabled where required. Docs https://docs.siliconflow.cn/docs/api/chat-completions-post, https://openrouter.ai/docs, https://cloud.google.com/translate/docs/reference/rest/v2/translate.

## Doclingo
https://doclingo.ai/zh/doclingoApi confirms paid API; free website characters cannot be used. Public page does not expose the authenticated endpoint/request schema. Integration blocked pending official developer documentation; no guessed endpoint or private browser API.

## Diagnostics
Last 300 allowlisted in-memory events only. No manuscript text, URLs, file names, task IDs, keys or raw exceptions. View/refresh/clear in preferences; manually copy report. Raw upstream/Zotero logs outside this report are not certified sanitized. No telemetry upload.

2026-11-27: official Doclingo launch article links to https://doclingo.cn/en/doclingoApi/ApiDoc (redirects to doclingo.vip); both that route and the Chinese developer page could not be retrieved in the current verification. Obtain the authenticated documentation from the developer console or support@doclingo.ai before implementing any request. No guessed endpoints.

## BelinDoc signed PUT (macOS 15.7.1 / Zotero 10.0.9 live test)
User-reported live acceptance on fc08a72: authentication, model, quota and presign requests succeeded. PUT failed with S3 HTTP 403 SignatureDoesNotMatch even with the official curl example; X-Amz-SignedHeaders included content-disposition. No translation task was submitted. The REST docs https://belindoc.com/docs do not specify the exact signed Content-Disposition value. The plugin now inspects signed header names, uses the anonymous document.pdf filename, sends only supported signed headers, exposes a local override for disposition, and preserves the HTTP status and allowlisted storage code without logging the URL or XML. Default candidate `attachment; filename="document.pdf"` is NOT live-verified; if rejected, obtain the exact header from BelinDoc or its official MCP upload_document tool (https://belindoc.com/mcp). If content-type is signed, use application/pdf. Unknown signed headers fail before upload. No automatic repeated PUT or translation submission after failed upload. For a no-translation-quota test use only a synthetic single-page PDF, fresh URL, PUT and stop before confirming translation. Never share the presigned URL, credential, raw S3 XML or actual document name. Reference: https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html. Live acceptance is still open. Local report also confirms original JACC and XunZi layout regressions with synthetic translations, not actual translation quality.

## PaddleOCR AI Studio (experimental)
Choose PaddleOCR under PDF parsing engine and enter an AI Studio Access Token; the default model is PaddleOCR-VL-1.6, with PP-StructureV3, PaddleOCR-VL-1.5 and PaddleOCR-VL supported as explicit alternatives. The official AI Studio API is distinct from paid Baidu Cloud OCR. The published page quota is account/model dependent and subject to change; no paid endpoint or automatic paid fallback is configured. Obtain the token from https://aistudio.baidu.com/; reference https://www.paddleocr.ai/main/version3.x/inference_deployment/serving/paddleocr_official_api/typescript.html and https://ai.baidu.com/ai-doc/AISTUDIO/fml7mozw5. The client independently implements the documented asynchronous multipart POST /api/v2/ocr/jobs, job GET, BOS JSONL result download. It accepts at most 30 MiB / 1000 pages, validates complete ordered pages and result domains, sends no API credential to BOS, does not download remote figures, does not auto-resubmit, and requires user consent to upload full PDFs. Cloud jobs may continue after local cancellation. No real API account has been tested.
The normalizer reads prunedResult.parsing_res_list in reading order, uses pixel width/height and inverse PDF viewport transform, protects tables/formulas/figures and unknown labels, matches entire recognized text against local text line rectangles before allowing erasure. Invalid/mismatched geometry goes to continuation sheets, not a broad white overlay. Unrecognized PDF.js text stays original and is reported. For scanned PDFs with no trustworthy physical text lines, translation is on continuation sheets rather than destructive in-place replacement. This is an improvement to layout analysis, not full BabelDOC typesetting or vector-preserving right-page reconstruction. No claim of perfect scientific accuracy. See https://www.paddleocr.ai/v3.6.0/en/version3.x/pipeline_usage/PaddleOCR-VL.html.
