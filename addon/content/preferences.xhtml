在 Zotero 10 新 PDF 阅读模式中按段落显示英文原文和中文译文。默认使用 Translate for Zotero（推荐使用google，其次必应）；Ollama 作为可选后端保留。 翻译后端 Translate for Zotero（推荐） Ollama 固定跟随 Translate for Zotero 当前默认服务。请在 Translate for Zotero 中切换服务或配置密钥。 Bilingual Reader 只负责分段、调度、缓存和双语排版。 点击普通 PDF 阅读器工具栏的「📑」可直接由 PDF.js 读取原始页面文字与坐标， 生成完整原始 PDF 页面 + 可复制中英译文页。直接复制原始 PDF 页面（非截图），保留图片、文字层及矢量图形；原始附件不修改。 PDF 解析引擎 PDF.js（内置，推荐） Docling（本地增强，可选） MinerU（云端 API） Mistral OCR（云端 API） LlamaParse（云端 API） 本地 Docling 地址 测试连接 Docling 需要另行在 Mac 安装 Python 与 Docling，然后运行源码中的 scripts/docling_local_server.py。Docling 仅连接 127.0.0.1/localhost；首次离线使用可能需要提前下载模型。 若 Docling 服务不可用，可手动回退 PDF.js。 MinerU Token 模型（vlm / pipeline） Mistral API Key OCR 模型 LlamaParse API Key 解析档位（agentic 等） 云端解析服务使用各自独立 API Key，上传整个 PDF 前需确认，可能计费并由服务商处理数据。 密钥保存在 Zotero 本地偏好中，不是系统钥匙串；清空后保存可移除。PDF.js/Docling 解析不上传 PDF 到云端。 旧版重排导出附加原始 PDF 全页（推荐，避免漏图；文件会增加页数） 不翻译末尾页数 默认 1 页。常用于跳过论文最后的参考文献页；设为 0 表示不按页数跳过。 插件同时继续跳过 Zotero 已明确标记为参考文献的结构化段落。页数限制按 PDF 物理页计算。 最大并发请求 默认 2。通常比完全串行明显更快，同时避免一次发出过多请求。 请求启动间隔（毫秒） 默认 250。公共免费服务若频繁限流，可提高到 500–1000。 单次请求最大字符数 默认 2800。超长段落会自动拆成较小片段，降低大文本请求失败概率。 单次合并段落数 默认 6。短段落会在字符上限内合并请求；标记未被翻译服务保留时会自动逐段重试。设为 1 可关闭合并。 单次请求超时（毫秒） 默认 60000。防止失效服务永久占用任务；使用较慢的本地模型时可提高。 连续失败后暂停 默认 3 次。避免失效服务持续请求整篇论文。 保存设置 清除翻译缓存 缓存采用自动上限和最近使用淘汰，避免长期阅读后偏好存储无限增长。 服务地址 模型 测试 Ollama 连接 修改翻译后端或速度参数后，回到 PDF 阅读器点击 🔄。插件会取消旧任务、清除旧错误结果，并按照当前设置重新调度未成功的段落。 https://github.com/quillamio/bilingual-reader
